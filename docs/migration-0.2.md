# 从 0.1 升级到 0.2

## 接口

运行创建现在返回 `202 Accepted`，而不是等待执行结束后返回 `200`。保存响应的 `id`，通过 `GET /api/runs/{id}` 或 SSE 读取进度；`SUCCEEDED / FAILED / MANUAL_REVIEW` 是终态。创建时可发送 `Idempotency-Key`，同工作流同键同输入会返回原运行，异参返回 409。

## 数据

0.2 默认 H2 文件为 `./data/flowtrail-runtime-v2`。启动器不会打开或覆盖旧 `./data/flowtrail`。MySQL 使用独立数据库及 Flyway 初始化。

迁移步骤：

1. 停止旧服务并完整备份旧 `data/`。复制的数据库文件应在旧服务停止后取得。
2. 用旧版本启动备份副本，经 `GET /api/workflows` 导出定义，经各工作流的运行历史接口导出完成历史（该接口每个工作流最多 50 条；更多历史可从备份中的 `runs` 表导出）。
3. 将定义中的 `name / nodes` 通过新服务 `POST /api/workflows` 导入。新 ID 可用单独映射表保留。
4. 旧完成历史作为只读 JSON 归档保留。不要将其转换成节点检查点，也不要将旧 `runs` 表改写成新 `workflow_run`。
5. 用离线模板和新建运行核对新库，再切换本地客户端。保留旧备份以便回查。

运行快照与检查点从新建的 0.2 运行开始产生。备份/导出动作由使用者显式执行，升级程序不会自动迁移或删除旧数据。
