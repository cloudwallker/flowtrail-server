# FlowTrail Server 后端实现说明

## 实现范围

后端位于 `dev.flowtrail` 包，使用 Spring Boot Web、JDBC、H2 和 Java 21 虚拟线程。实现包括 8 个 API 路径、工作流定义校验、稳定拓扑执行、引用解析、受限 HTTP 客户端、H2 持久化、统一错误响应与严格 JSON 类型绑定。

## DAG 与引用

定义校验先规范化节点默认值，再检查 id、节点数量、重复 id、未知依赖、重复依赖、自依赖和环。拓扑排序使用定义位置作为就绪队列优先级，因此对同一份定义总能返回相同顺序。祖先集合沿拓扑顺序计算，`${nodeId.output}` 只能读取传递依赖中的节点；兄弟节点、后继节点和无关节点引用都会在保存前拒绝。

运行输入会在创建运行记录和执行任何节点之前完整检查。引用解析使用单次扫描，插入值不会被再次解释。TEXT 与 HTTP 的 URL、正文、请求头名称和请求头值共享相同解析规则。解析器在追加每一段文本前计算结果长度，每个插值结果最多包含 262144 个 UTF-16 code unit，超限不会先构造完整字符串；节点记为 `FAILED`，后续节点记为 `SKIPPED`，最终 Run 正常持久化。

## HTTP 执行边界

HTTP 传输使用 Apache HttpClient5，并显式调用 `disableAutomaticRetries()` 和 `disableRedirectHandling()`。每个调用在虚拟线程中同步读取响应，外层截止时间覆盖连接、响应头和完整响应正文；超时、读取异常或正文超限时先取消请求，再关闭正文流并取消任务，避免 chunked 流关闭时为复用连接而排空剩余正文。读取过程在 256 KiB 后立即停止。非 2xx 响应只记录状态码，不保存响应正文。动态 URL 在解析后检查协议、主机、凭据和 fragment。

工作流执行方法没有数据库事务，网络等待不会占用数据库事务。所有节点完成或停止后一次写入最终 Run；控制器收到返回值时记录已经持久化。失败节点之后的所有未执行节点写为 `SKIPPED`。

## 持久化

`workflows` 保存名称、原定义顺序的节点 JSON 与创建时间。`runs` 保存最终状态、输入、拓扑执行顺序的节点结果和起止时间。表由幂等 `schema.sql` 初始化，运行历史通过 `(workflow_id, started_at)` 索引查询并限制为 50 条。

## 错误与输入安全

API 错误统一为 `{code,message}`。业务校验错误为 400，无效 JSON 和类型不匹配为 400，不存在为 404，其他异常为通用 500。内部异常只写服务日志，响应不包含异常、请求体、错误 HTTP 正文或数据库内容。

Jackson 对文本、整数和枚举采用严格绑定：数字、布尔值不能变成字符串，字符串、小数和布尔值不能变成整数，数字不能变成枚举。未知字段与重复 JSON 字段由应用配置拒绝。

## 已知边界

服务没有认证、授权、租户隔离、域名/IP 出站策略和分布式执行能力，只适合本地学习与受信环境。执行为同步串行模式；单个请求会等待整个工作流结束。HTTP 响应按 UTF-8 转成字符串，不做内容类型转换。服务进程在最终 Run 写入前被强制终止时，本次同步运行没有可恢复的中间状态。
